## 0. 背景と目的

2026-11-10 の7局（`docs/playtest/2026-11-10/`）では、1局が534〜593選択、1席あたり約190選択だった。現行の `move` は、適用した出来事の後に `show` の全文を付けて返す（`tools/play/cli.ts` の `case 'move'`）。`--brief` を付けても70〜110行あると複数の席が知見に記し、少なくとも6席が自分で grep・sed を書いて出力を絞った。打ち手の会話は呼び出しのたびに伸びるため、1回の出力の長さは呼び出し回数と掛け算で効く。

目的は、打ち手が判断に使う情報を落とさずに、1席あたりの読む量を減らすことである。目安は、1席あたりのコマンド出力の合計文字数を従来の3分の1以下とする（完了条件ではなく、報告する値である）。

なお、0 の数値のうち行数は各席の知見の記述によるもので、チャット側では実測していない。2-7 の計測で確かめること。

## 1. 守ること

- ルールを再実装しない。合法手は `getOptions`、進行は `applyMove`、得点は `finalScores`、派生値は `queries` だけから得る。足りない派生値は `src/game/queries.ts` に足す。
- 選択肢 ID、選択肢の並び順、番号（1始まり、`getOptions` の順）、乱数の消費順を変えない。`Option.label` の文言も変えない（短い表示は 2-4 のとおり表示の側で作る）。
- 非公開情報の規則（19-6-1、CLAUDE.md「対話プレイ用のコマンドの約束事」）は、新しい出力のすべてに同じく適用する。視点以外の手札の内容と山札の順序を出さない。
- 記録の形（`ReplayRecord`）を変えない。既存の記録が読めること。
- 既定の出力を短い形に変える。従来の全文は明示的に求めたときだけ出す（2-1）。オンライン版の `online show|wait|move` にも同じ変更を適用する。
- 新しいライブラリを導入しない。配布用ビルドとオンラインのビルドに含めない。

## 2. 作るもの

### 2-1. `move` の戻りを差分にする（項目1）

- `move` の既定の出力を次の3つだけにする。
  1. 適用した選択で起きた出来事（現行の `renderSteps`）
  2. 自分の状態の要約1〜2行（金、資材、生産力、軍事力トークン、通常・臨時ワーカーの使える数、軍事レベル、インフラレベル、得点トラック）
  3. 次の選択待ちが自分（`--seat` の席。なければ選択待ちのプレイヤー）なら選択肢（2-4 の形）。他の席なら「選択待ち：P1」の1行
- 全局面は `show` を明示的に呼んだときだけ出す。`move --full` は従来どおり出来事の後に `show` の全文を出す。
- `undo` と `new` の出力も同じ考え方にする（`undo` は取り除いた選択肢 ID と選択肢だけ、`new` は従来どおり全文）。
- 目安：`move` の既定の出力は、選択肢を除いて15行以内。

### 2-2. 変わらない文言の分離（項目2）

- コマンド `ref [--seat <番号>] [--only <欄,...>]` を加える。対局中に変わらない文言をまとめて出す。
  - アクションボードの各スペースの効果文と必要ワーカー数、共有かどうか、最上位の解放条件
  - 全席のキャラクターの能力
  - ボーナスタイルの内容（場に出ているもの）
  - 襲撃カードの内容、建物の種類ごとの効果と上限、フリーアクションの一覧
- `show`・`wait`・`move` の既定の出力からは、上の文言を省く。アクションボードは「置かれているスペースと、置いたプレイヤー」だけを出し、誰も置いていないアクションの行は出さない。キャラクターの能力文、ボーナスタイルの内容は ID と名前だけにする。
- 対局中に新しく公開されるもの（公開された特別な市民カード、計画都市カード、引いた文明カード、取り替えたボーナスタイル）は、公開・獲得した時点の出来事に内容を1回だけ出す。以後の `show` では ID と名前だけにする。
- 手札は `show` の「自分」の欄で、番号・名前・割引後のコスト・タグ・固有得点までを1行ずつ出し、効果文は `show --only hand`（2-3）または `ref` のカード指定（`ref --card <番号,...>`）で出す。
- 従来の全文は `show --full` で出す。現行の `--brief` は `--full` を付けない既定の形に吸収し、指定されても誤りにしない（何もしない）。

### 2-3. 欄の指定（項目3）

- `show`・`wait`・`move` に `--only <欄,...>` を加える。指定した欄だけを、指定の順ではなく既定の順で出す。
- 欄の名前：`progress`（進行）、`raid`（襲撃）、`actions`（アクションボード）、`shared`（共有の場）、`self`（自分）、`hand`（手札。効果文つき）、`others`（他のプレイヤー）、`board`（個人ボード）、`events`（出来事）、`options`（選択肢）。
- 知らない欄の名前は、使える名前の一覧を添えて失敗する。
- `--json` にも同じ指定が効く（指定した欄のキーだけを出す）。

### 2-4. 選択肢を畳む（項目4）

- 同じ種類の選択肢が並ぶときは1行にまとめる。まとめた行でも各選択肢の番号と ID が読め、番号でも ID でも指せること。
  - `free:civcard_to_materials:*` のように、対象のカードだけが違う選択肢：「手札を資材1に替える：12.045「名前」 13.058「名前」 …」の形にする。
  - カードを選ぶ選択肢（プレイ・捨てる・獲得）：番号・ID・名前・コストまでにし、効果文を付けない。
  - マスを対象にする選択肢：現行のマスごとのまとめ（`optionLines`）を、選択肢が8個を超えたら効かせる（現行は24個を超え、かつマス対象が12個を超えるとき）。
- まとめ方は選択肢 ID の接頭辞と `targetOf` の種類だけで決め、カードやアクションごとの個別の分岐を書かない。
- `--full` のときは従来どおり1選択肢1行でラベルの全文を出す。
- 個人ボードの地図は、選択肢がマスを対象にしていても既定では出さない（`--board` か `--only board` のときだけ出す）。

### 2-5. 他の席の出来事の要約（項目5）

- `wait` の「前回の選択の後に起きたこと」は、他の席の分を手番ごとに1行にまとめる。1行は「誰が、どのアクションを（段階つき）、何が増減したか」とする（例：「P1 建築・上位：住宅2・役所1、資材−7、インフラ+1、得点+2」）。
- 手番のまとめと増減の合計は、記録の再生画面が使っている既存の関数（`replayTurns` と手番全体の増減の合計）を使う。`tools/play/` の側で増減を計算し直さない。画面と共用できる形になっていなければ、`src/game/` の側に移して両方から読む。
- 自動で進んだ処理（収入、襲撃の判定、ラウンドの区切り）は、自分に関わる増減と、全員に共通の結果だけを出す。
- 自分の選択で起きた出来事は従来どおり選択ごとに出す。
- 詳細が要るときのために、`log --from <手数>` は変えない。現行の「最後の40手だけ」の打ち切りは、手番ごとのまとめに置き換える。

### 2-6. ラウンドごとの打ち手の作り直しを支える（項目6）

打ち手（席ごとのエージェント）をラウンドの区切りで作り直し、会話の履歴を持ち越さずにノートだけを引き継ぐ運用にする。作り直しそのものは対局を回す側（親のエージェント）の仕事であり、コマンドは次を備える。

- `wait --seat <番号> --round <ラウンド番号>`：局面のラウンドが指定より先へ進んでいたら、番を待たずに「ラウンド <番号> は終わった」と出して終了コード0で終える。打ち手はこれを見て、ノートを書いて終了する。ドラフトと準備は第1ラウンドに含める。
- `resume --seat <番号>`：作り直した打ち手が最初に呼ぶ。`ref` の内容、`show --seat <番号>` の内容、その席のこれまでの手番ごとのまとめ（2-5 の形）、いま終わったときの得点の見込み（`score` のその席の分）を1回で出す。
- ノートの置き場は `.play/notes/P<席>.md` とする。コマンドはノートを読み書きしない（打ち手が自分で読み書きする）。上限と書く内容は 3-1 の指示に書く。

### 2-7. 出力量の計測

- `tools/play/measure.ts` と `npm run -s play:measure -- --file <記録>` を加える。記録を先頭から再生し、各席が「自分の選択のたびに `move` を1回、番が回ってくるたびに `wait` を1回呼んだ」と仮定したときの、席ごとの出力の合計文字数と行数を出す。従来の形（`--full`）と新しい既定の形の両方を出し、比を添える。
- 実際の打ち手の呼び出し方とは一致しない近似である。その旨を出力の末尾に1行で書く。
- `docs/playtest/2026-11-10/replays/game5.json` で実行し、結果を報告に含める。

## 3. 運用文書（`docs/playtest/`）

### 3-1. 打ち手への指示（項目6・8）

`docs/playtest/player-brief.md` を作る（2026-11-10 の対局で使った player-brief.md がリポジトリにないため、新しく書く）。内容は次のとおりとし、3KB 以内に収める。

- 目標（自分の最終得点を最大にする）と、席・記録ファイル・ノートの場所
- 呼び出しの手順：最初に `resume --seat N`、以後は `wait --seat N --round R` と `move ... --seat N`。全局面が要るときだけ `show --only <欄>` を使う。`--full` は使わない
- ノート（`.play/notes/P<席>.md`）：ラウンドの終わりに上書きする。1.5KB 以内。書くのは、方針、次のラウンドに最初に打つ手、狙っているカード・マス・ボーナスタイル、気づいたルールの穴と分かりにくい箇所。局面の写しは書かない（`resume` で出る）
- 対局後の知見の書式（3-3）
- 他の席の記録・ノート・知見を読まないこと。一時ファイルは席ごとの名前にすること

### 3-2. 打ち手の起動場所（項目8）

- 打ち手はリポジトリの外の作業ディレクトリで起動する。リポジトリの CLAUDE.md（65KB、実装向け）が打ち手の会話に読み込まれないようにするためである。
- `dist-play/cli.js` を、リポジトリの外の任意のディレクトリから `node <リポジトリ>/dist-play/cli.js ...` で呼べることを確かめる（記録とノートの既定の場所は、呼び出したディレクトリからの相対パスになる）。動かない箇所があれば直す。
- 対局を回す手順（ビルド、作業ディレクトリの用意、`player-brief.md` と `knowledge-play.md` の写し、席ごとの起動、ラウンドごとの作り直し、対局後の記録と知見の回収）を `docs/playtest/README.md` に書く。

### 3-3. 知見ファイルの分割（項目7）

- `docs/playtest/knowledge-play.md` を作る。打ち手が対局の前に読む要約で、3KB 以内とする。`docs/playtest/2026-11-10/knowledge.md` から、打つ手の判断に使う内容だけを抜き出す（勝ち筋、キャラクターごとの要点、落とし穴、コマンドのこつ）。対局結果の表、ゲームごとの経緯、バランスの気になる点は入れない。冒頭に、過去の観察であって鵜呑みにしないこと、準拠したデータの版（`DATA_VERSION`）を書く。
- `knowledge.md` はそのまま経緯の記録として残す。打ち手には読ませない。
- 対局後の各席の知見は、次の書式で 2KB 以内とする：最終得点と内訳1行、効いたもの3つまで、誤りだった判断3つまで、`knowledge-play.md` に書かれていない新しい発見、ルールの穴・分かりにくい箇所、コマンドへの要望。`knowledge-play.md` に既にある内容を繰り返さない。
- `knowledge-play.md` の更新は、対局を回す側が対局の後にまとめて行う（3KB を越えたら古い内容を削るか統合する）。

## 4. テスト

`tests/play-cli.test.ts` に加える。純粋関数（`record.ts`・`render.ts`・`measure.ts`）を対象とする。

- 既定の `move` 相当の出力：乱択プレイアウトの全選択を通じて、選択肢を除いた行数が15行以内である。次の選択待ちが自分なら選択肢を含み、他の席ならその席の選択肢（手札の内容を含みうる）を含まない。
- 畳んだ選択肢：全選択待ちを通じて、畳んだ表示から読み取れる番号と ID の組が、`getOptions` の順の番号と ID の組に一致する（欠けも重なりもない）。
- `--only`：各欄を単独で指定した出力が、`--full` の出力の該当する欄と同じ情報を持つ。知らない欄は失敗する。
- `ref`：アクションボードの全スペースの効果文を含む。視点以外の手札の内容を含まない。
- 非公開情報：既定・`--only`・`ref`・`resume`・手番ごとのまとめのすべてで、視点以外の手札のカード番号と名前、山札の順序が現れない。他の席が引いたカードは枚数だけである。
- 手番ごとのまとめ：他の席の1手番の増減の合計が、その手番の前後の局面の差と一致する。
- `wait --round`：ラウンドが進んでいれば、番でなくても終わる。
- `--full`：従来の `show`・`move` の出力と一致する（既存の150行以内の検査は `--full` に対して残す）。
- 既存の記録：`docs/playtest/2026-11-10/replays/` の7局が終局まで再生でき、最終得点が README の値と一致する。
