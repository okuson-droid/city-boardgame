# Claude Code への指示書：`wait`・`resume` の既定の出力を縮め、手番の終わりと番待ちを1回にする

作成日：2026-11-12（ユーザー決定 2026-11-12「この下書きの通りに進めて」。decisions.md 3-7）
実施：2026-11-12 に実装し、確認の対局（指示書 5）はゲーム13（`docs/playtest/2026-11-12-game13/`）で行った。
準拠するルール：claude/rules.md v0.8 と、リポジトリの `docs/dev/rules-and-data.md`。本指示書はルールと数値を変更しない。
対象：対話プレイ用のコマンド（`tools/play/`）と、打ち手への指示（`docs/playtest/player-brief.md`）
対象外：ルールと数値、選択肢 ID・並び順・乱数の消費順・`Option.label`・記録の形、ローカル UI・オンラインの窓口・チューナー、`show`・`move` の既定の出力（本指示書で触れる所を除く）
根拠：AI 同士の対局3局（ゲーム10〜12、打ち手45人）の効率化の方法（`docs/playtest/2026-11-12-game10/`・`-game11/`・`-game12/` の `proposals.md`）。ユーザー決定（2026-11-12、おすすめを採用）

## 0. 背景と目的

3局・45人の案で、次の3つが毎局上位だった（人数はゲーム10／11／12）。

| 案 | 人数 |
|---|---|
| A. `wait` の既定の出力を縮める | 11／10／14 |
| B. `resume` を短くする | 7／12／12 |
| H. 手番の終わり・番待ち・次の手を1回にする（`--then-wait`）、`wait` の時間切れの見直し | 0／6／5 |

観察された事実は次のとおりである。

- `wait` の既定は番が来るたびに局面全体と選択肢（30〜36行、約5KB）を出す。打ち手は前回と同じ欄を読み直し、指示書で禁じた `head`・`tail`・`sed`・`grep` で自分で絞った（3局のほぼ全席）。`--only progress` を付けると約10分の1になった（ゲーム12 P0R5 の実測）。
- `resume` は約7〜25KB で、アクションボードの効果文・ドラフト候補のキャラクター・建物表・済んだ襲撃カード・過去の手番を毎ラウンド出す。第2ラウンド以降の打ち手は、ノートと `ref` で足りると報告した。
- 手番ごとに `move ... end`・`wait`・次の `move` を別々に呼ぶため呼び出しが増え、打ち手はシェルで `move ...; wait ...` をつないだ。
- `wait` の既定の時間切れ（300秒）が、打ち手の道具の上限（約120秒）より長い。待つ間に道具側で打ち切られ、裏に回った出力を読み直す例が、ゲーム11・12で5人あった。

目的は、得点を下げずに打ち手1人あたりの読む量と呼び出しの回数を減らすことである。

## 1. 守ること

- 指示書 2026-11-11・2026-11-12 の約束（ルールを再実装しない、非公開情報 19-6-1、事実だけを出し助言しない、選択肢 ID・並び順・記録の形を変えない）を保つ。
- 省いた情報は、既存のコマンド（`show --only`・`ref`・`log --seat`）で必ず引けること。新しい情報を足さない。
- 従来の出力は `--full`（全文）と、本指示書で加える `--state`（`wait`）・`--ref`（`resume`）で引けること。
- オンライン版の `online wait|move` にも、伏せた写しで求められる範囲で同じ変更を適用する。

## 2. 作るもの

### 2-1. `wait` の既定の出力を縮める（A）

- 番が来たときの既定の出力を、次の順の欄だけにする。
  1. 出来事（従来どおり、他の席は手番ごとに1行）
  2. 狙いの知らせと手番順の行（指示書 2026-11-12 2-4。従来どおり）
  3. 襲撃の行：ラウンドの最初の番だけ（公開中の襲撃カードと、自分の防衛・撃退に払うトークン）
  4. 置かれたスペースの1行（従来の局面の欄の1行と同じ）
  5. 自分の要約1行（`move` の出力と同じ `selfSummary`）
  6. 選択肢（従来の畳んだ形）と注意（指示書 2026-11-12 2-3）
- 「選べないアクション・建物・遠征の報酬」の理由の行は、前回の `wait` から変わったものだけを出し、変わらないものは「選べない N 件（理由は show --only options）」の1行にする。前回の内容の置き場は、狙いと同じファイル（`plan-P<席>.json`）に持つ。
- 局面の残りの欄（進行・共有の場・自分の詳細・他のプレイヤー）は出さない。`--state` を付けると従来の既定の出力（局面全体）を出す。`--only` は従来どおり。
- 行数の上限：選択肢・注意・選べない理由を除いて、出来事の行数＋6行以内。テストで確かめる。

### 2-2. `resume` を短くする（B）

- 既定の出力を、次の欄だけにする。
  1. 局面（2-1 の縮めた形ではなく、従来の `show` の既定の形。作り直した打ち手は局面を一度は全体で見る必要があるため）
  2. 手札（効果文つき）
  3. 自分のキャラクターの能力の文、自分の特別な市民カードと公開中の特別な市民カード・計画都市の文（`ref --only public` の自分と場の分）
  4. このラウンドの手番順の行、狙いの一覧（`plan` の一覧と同じ）
  5. 得点の見込み1行
- 省くもの：アクションボードの効果文、ドラフト候補と他の席のキャラクターの能力、建物表、フリーアクション表、襲撃カードの一覧（公開中の1枚は 1 の局面に入る）、遠征の報酬表、その席のこれまでの手番ごとのまとめ。いずれも `ref`・`log --seat` で引ける旨を末尾に1行で書く。
- 第1ラウンド（ドラフトと準備を含む）だけは従来どおり `ref` の全文を含める。`--ref` を付けるといつでも従来の全文を出す。

### 2-3. 手番の終わりと番待ちを1回にする（H）

- `move <選択肢...> --seat N --then-wait [--round R] [--timeout 秒]` を加える。選択肢を適用した後、選択待ちがまだ N なら従来の `move` の出力で終える。選択待ちが他の席に移ったら、そのまま `wait --seat N` と同じく番を待ち、番が来たら 2-1 の形で出す（`move` の出来事と `wait` の出来事を続けて出す）。`--round R` で指定のラウンドが終わったら、`wait --round` と同じ文で終える。
- `end`・`pass` を自動で補わない（打ち手が並べる）。
- `wait` と `--then-wait` の既定の時間切れを 100 秒にする（打ち手の道具の上限 約120秒より短くする）。時間切れの文は従来どおり「もう一度 wait を呼ぶこと」とする。

### 2-4. 打ち手への指示（`player-brief.md`）

3KB 以内のまま、次を改める。加えた分は既存の記述を詰めて収める。

- 手順：番を待つのは `move ... end --then-wait` か `wait`。`wait` の既定は出来事と選択肢だけで、局面全体が要るときだけ `show --only <欄>` か `wait --state`。
- 選択肢 ID の型を1行で載せる：`act:<アクション>:<段階>`・`temp:N`・`count:N`・`tile:<マス>:<地形>`・`build:<建物>:<マス>`・`reward:N`・`card:<番号>`・`sc:<番号>`・`end`・`pass` の後に `bonus:N`（3局で計15人が求めた。まとめの D 案）。

## 3. テスト

- `wait`：番が来たときの既定の出力が、選択肢・注意・選べない理由を除いて「出来事の行数＋6行」以内である。`--state` の出力が従来の既定の出力と同じである。選べない理由の行は、前回から変わらなければ1行にまとめる。
- `resume`：第2ラウンド以降の既定の出力に、アクションボードの効果文・他の席のキャラクターの能力・建物表が現れない。第1ラウンドと `--ref` では従来どおり現れる。
- `--then-wait`：選択待ちが同じ席なら従来の `move` と同じ出力、他の席に移れば番を待って 2-1 の形を出す。`--round` で終える。記録は `move` と同じに変わる。
- 非公開情報：縮めた `wait`・`resume`・`--then-wait` のすべてで、視点以外の手札の内容と山札の順序が現れない。
- 既存のテスト（`tests/play-cli.test.ts`・`tests/play-strength.test.ts`）が通る。
