作成日：2026-11-10
準拠するルール：claude/rules.md v0.8 と、リポジトリの CLAUDE.md「ユーザー決定のうち design/ に未反映のもの」（2026-11-03〜11-07 の決定）。本指示書はルールを変更しない。
確認したリポジトリの状態：okuson-droid/city-boardgame の main、commit 14876e6（2026-11-09「調整案『新しい調整案』を反映する」）
作業ブランチ：`feat/play-cli`
対象：画面を通さずに、文字の入出力だけで1局を最後まで打てるコマンドの追加
対象外：プレイ AI と自己対戦の統計（balance-sim の領分）、オンライン対戦の席への参加、ローカル UI・オンライン・チューナーの変更、ルールと数値の変更

## 0. 目的と使われ方

Claude（チャット側）がこのゲームを実際にプレイし、路線の強さの感触、ルールの穴、分かりにくい箇所を確かめるための道具である。Claude は作業環境のシェルからコマンドを1回ずつ呼び、出力された局面と合法手を読んで、次の手を選ぶ。したがって次を満たすこと。

- 1回の呼び出しで完結する。対話的な入力待ち（プロンプト、readline）を作らない。
- 局面は呼び出しをまたいでファイルに保存する。
- 出力は文字だけで読める。画面のアイコンに頼らない。
- 人が同じコマンドで遊ぶこともできるが、人向けの見た目の作り込みは要らない。

## 1. 守ること

- ルールを再実装しない。合法手は `getOptions`、進行は `applyMove`、得点は `finalScores` だけに頼る。コマンドの側で合法かどうかを判定しない。
- `src/game/` の公開窓口（`src/game/index.ts`）から読む。表示に必要な派生値が足りない場合は、`src/game/queries.ts` に関数を追加し、コマンドの側で計算しない。
- 選択肢 ID の付け方と乱数の消費順を変えない（通信プロトコルの一部である）。`Option.label` の文言は改めてよい（2-5）。
- `Math.random()` を使わない。シードは引数で受ける。
- 配布用ビルド（`npm run build`）とオンラインのビルドに、このコマンドのコードを含めない。
- 新しいライブラリを導入しない。
- 調整の対象になりうる数値をコマンドの側に書かない。

## 2. 作るもの

### 2-1. 置き場と起動

- `tools/play/` に置く。構成は次のとおりとする。
  - `record.ts`：対局の記録の読み書きと、記録からの局面の再生（純粋関数とファイル入出力を分ける）
  - `render.ts`：局面と選択肢を文字にする純粋関数
  - `cli.ts`：引数の解釈と入出力だけを行う薄い入口
  - `vite.config.ts`：Node 向けのビルド設定
- `src/data/index.ts` は JSON の import と `import.meta.glob` を使うため、Node で直接は実行できない。`server/` と同じく Vite で Node 向けにビルドしてから実行する。
  - `npm run play:build`：`dist-play/cli.js` を作る。
  - `npm run play -- <コマンド> [引数]`：`dist-play/cli.js` を実行する。ビルドは行わない（毎回のビルドを避けるため）。`dist-play/cli.js` がなければ、`npm run play:build` を先に実行するよう伝えて終了コード1で終える。
- `dist-play/` と `.play/`（記録の既定の置き場）を `.gitignore` に加える。

### 2-2. 対局の記録

- 記録は JSON ファイル1つとし、`{ config, seed, moves }` を持つ。`moves` は選択肢 ID の列である。局面は常に `replay(config, seed, moves)` で作り直す。GameState そのものは保存しない。
- ファイルは `--file <パス>` で指定する。省略時は `.play/game.json` とする。
- 記録には、再生時にデータが変わっていないかを確かめるため、`src/data/` のゲームデータの内容から作ったハッシュを持たせる。食い違う場合は警告を出し、再生が途中で失敗したら「データが変わったため再生できない」と伝えて終了コード1で終える。

### 2-3. コマンド

すべてのコマンドは `--file` を受ける。成功は終了コード0、失敗は1とし、失敗の理由を標準エラーに1行で出す。

- `new --players <3|4> --seed <整数> [--snake] [--names a,b,c]`
  - 新しい記録を作る。既にファイルがあれば上書きせずに失敗する（`--force` で上書きする）。`--snake` は `variants.snakeDraft` を指定する。
  - 作った後、`show` と同じ内容を出す。
- `show [--as <プレイヤー番号>] [--player <プレイヤー番号>] [--board] [--json]`
  - 現在の局面と、選択待ちのプレイヤーの選択肢を出す（2-4）。
  - `--as` は視点を指定する。省略時は選択待ちのプレイヤーの視点とする。
  - `--player` は、そのプレイヤーの詳細（2-4 の「自分」と同じ項目。ただし非公開情報は視点に従って伏せる）を出す。
  - `--board` は視点のプレイヤーの個人ボードを出す。選択肢がマスを対象にしている場合は、指定がなくても出す。
  - `--json` は同じ内容を JSON で出す。
- `move <選択肢> [<選択肢> ...]`
  - 選択肢を順に適用する。選択肢は、選択肢 ID か、直前の `show` の番号（1始まり、`getOptions` の順）で指定する。
  - 選択肢に存在しない指定が来た時点で止め、そこまでの適用も含めて記録を一切書き換えずに失敗する（全部通るか、何も変えないか）。
  - 成功したら、適用した選択で起きた出来事（2-6）を出し、続けて `show` と同じ内容を出す。
  - 選択待ちのプレイヤーが途中で替わっても、指定された選択肢は続けて適用する。Claude が全席を打つ場合と、席ごとに区切って打つ場合の両方に使うためである。
- `undo [<手数>]`
  - 記録の末尾から指定した手数（省略時は1）を取り除く。分析用の道具であるため、チェックポイントによる制限を掛けない。取り除いた選択肢 ID を出し、続けて `show` と同じ内容を出す。
  - 取り消しがゲームのルール上の巻き戻し（第15章）と異なることを、`--help` に1行で書く。
- `log [--from <手数>]`
  - 記録の選択肢 ID の列を、手数の番号・選択したプレイヤー・ラベルとともに出す。
- `score`
  - 終局していれば `finalScores` の内訳（基礎得点、5評価軸、その他、合計、順位、同点判定に使った値）を出す。終局していなければ、得点トラックの現在値だけを出し、終局していない旨を添える。
- `--help`
  - コマンドの一覧と例を出す。

### 2-4. 局面の出力

`show` の既定の出力は、次の順に並べる。150行以内に収めることを目安とし、行を減らすために1項目1行の「見出し: 値」の形を基本にする。表の罫線や色を使わない。

1. 進行：ラウンド、フェイズ、場面の見出し（`queries.sceneOf`）、手番順、パスした順、選択待ちのプレイヤー
2. 襲撃：そのラウンドの襲撃カード、防衛ラインと撃退ラインの累積値、結果ごとの内容（`queries.describeRaidOutcomes`）、各プレイヤーの軍事レベルと不足分（`queries.raidNeed`）
3. アクションボード：10アクション×3段階について、必要ワーカー数、内容（`queries.describeActionSpace`）、置いているプレイヤー（`queries.spaceUsers`）、共有スペースかどうか、視点のプレイヤーが最上位を解放しているかどうか
4. 共有の場：ボーナスタイル（番号、内容、持ち主）、公開中の特別な市民カード（番号、内容）、計画都市カード（名前、条件、恩恵、達成者と順位）、文明カードの山札と捨て札の枚数
5. 自分（視点のプレイヤー）：
   - キャラクターと能力、ボーナスタイル
   - 金、資材、金の生産力、資材の生産力、軍事力トークン
   - 通常ワーカー（使える数／総数／上限）、臨時ワーカー（`queries.workerSummary`）
   - 軍事レベル、インフラレベル、次の到達報酬
   - 建物の種類ごとの軒数と上限、土地タイルの枚数、最上位の解放状況
   - 獲得した特別な市民カード、使用済みのフリーアクションと専用スペース
   - 手札（番号、名前、割引後のコスト（`queries.playDiscount`）、タグ、固有得点、効果）
   - プレイ済みの文明カード（番号と名前。効果は `--player` のときだけ出す）
   - 自然公園カードの3セット
   - 得点トラックの現在値
6. 他のプレイヤー：1人につき2〜3行で、キャラクター、金、資材、生産力、ワーカー、軍事レベル、インフラレベル、建物の軒数、土地タイルの枚数、手札の枚数、得点トラックの現在値
7. 選択肢：番号、選択肢 ID、ラベル。選択待ちがどのタスクのものか（何を選んでいるのか、残りいくつ選ぶのか（`queries.remainingInTask`）、確定前のコスト（`queries.pendingBuildCost`））を見出しに添える。

効果の文章は、効果スクリプトから組み立てる既存の関数（`describeScript`）で作る。カードごとの文章を手で書かない。データの `text`（原本の文言）は、効果スクリプトと食い違うものがあるため表示に使わない。

個人ボード（`--board`）は、A〜F の6行を文字で並べ、7マスの行を半マスずらして出す。各マスは、座標、地形、置かれた土地タイルの種類、建物、マスボーナス、精霊チップを短い記号で表し、記号の凡例を末尾に付ける。選択肢がマスを対象にしている場合（`targetOf`）は、対象のマスに印を付ける。

### 2-5. 選択肢のラベル

`Option.label` だけを読んで、何を選ぶ手なのかが分かることを求める。現状のラベルには、内部の ID をそのまま含むものがある（例：`フリーアクション gold_to_materials`）。次の水準に満たないラベルは、`src/game/` の側で改める。

- 支払うものと得るものが分かる（例：「フリーアクション：金5 → 資材1」）。
- アクションの選択は、アクション名・段階・必要ワーカー数が分かる。
- カード・建物・マス・ボーナスタイル・特別な市民カードを選ぶ手は、番号だけでなく名前か内容が分かる。

ラベルの変更は表示だけに留め、選択肢 ID と選択肢の並び順を変えない。ラベルの文言を検査している既存のテストと、ラベルを表示している画面は、あわせて直す。

### 2-6. 出来事の出力

`move` の後に、適用した選択で起きた出来事（`GameState.events`）を、選択ごとに1行ずつ文字にして出す。資源・生産力・トラック・得点の増減、土地タイルと建物の配置、カードの獲得とプレイ、襲撃の結果、ラウンドの区切りが分かればよい。乱数や他のプレイヤーの選択をまたいで自動で進んだ処理（収入、襲撃の判定など）も含める。

### 2-7. 非公開情報

- 非公開情報は、文明カードの手札の内容と山札の順序である（rules.md v0.8 19-6-1）。`show`・`move`・`log` の出力は視点に従い、視点以外のプレイヤーの手札の内容を出さない。山札の順序はどの視点でも出さない。
- 出来事のうち、他のプレイヤーが引いたカードの内容は伏せる（枚数だけを出す）。プレイされたカードは公開する。
- `--json` の出力も同じ規則に従う。GameState をそのまま出さない。
- `--as all` は、分析用にすべてのプレイヤーの手札を出す。山札の順序は出さない。

## 3. テスト

`tests/play-cli.test.ts` に、`tools/play/` の純粋関数（`record.ts`・`render.ts`）を対象にした単体テストを置く。`cli.ts` は薄く保ち、入出力以外のロジックを持たせない。

- 記録の再生：`new` 相当の記録に選択を足していった局面が、`replay(config, seed, moves)` の局面と一致する。
- 不正な選択：存在しない選択肢 ID・範囲外の番号を含む `move` は、記録を変えずに失敗する。複数指定の途中で失敗した場合も、記録は変わらない。
- 番号の指定：番号での指定が、同じ位置の選択肢 ID での指定と同じ局面になる。
- 取り消し：`undo n` の後の局面が、末尾 n 手を除いた記録の再生と一致する。
- 非公開情報：視点を指定した `show`（文字と JSON の両方）に、視点以外のプレイヤーの手札のカード番号・名前が現れない。山札の順序が現れない。`--as all` でも山札の順序が現れない。
- 1局の通し：既存の乱択プレイアウト（`tests/helpers/playout.ts`）の選択の列を、3人・4人それぞれ複数のシードで `move` 相当の関数に通し、終局まで進む。途中のすべての選択待ちで `show` 相当の関数が例外を出さずに文字を返す。`score` 相当の出力の合計が `finalScores` と一致する。
- ラベル：全選択待ちを通じて、ラベルに内部の ID（英字のスネークケース、`char:`・`civ:` などの接頭辞）が残っていないことを、乱択プレイアウトの中で確かめる。
- 行数：乱択プレイアウトの途中の `show` の既定の出力が、150行以内に収まる（個人ボードを除く）。
