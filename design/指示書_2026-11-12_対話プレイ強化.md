# Claude Code への指示書：対話プレイの打ち手を強くする（トークン量は据え置き）

準拠するルール：claude/rules.md v0.8 と、リポジトリの `docs/dev/rules-and-data.md`（rules.md からの変更とユーザー決定）。本指示書はルールと数値を変更しない。
確認したリポジトリの状態：okuson-droid/city-boardgame の main、commit 5aee056（2026-11-12 朝の時点）
作業ブランチ：`feat/play-strength`（本指示書と decisions.md を `design/` に置いた commit を含む。ここから続ける）
対象：対話プレイ用のコマンド（`tools/play/`）と、それが読む `src/game/` の派生値、対局の運用文書（`docs/playtest/`）
対象外：ルールと数値の変更、選択肢 ID・並び順・乱数の消費順の変更、ローカル UI・オンラインの窓口・チューナーの変更、コードが手を選ぶプレイ AI（貪欲・探索。balance-sim の領分）
根拠：decisions.md 3-6（ユーザー決定 2026-11-12、4項目を採用）

## 0. 背景と目的

打ち手1人あたりのトークン量を増やさずに、打ち手の得点を上げる。考え方は、打ち手のトークンを「暗算」と「読み違いの後始末」に使わせず、差がつく判断に回すことである。

これまでの対局（`docs/playtest/2026-11-10/`・`2026-11-11/`）で分かっていることは次のとおりである。

- 得点の差の中心は序盤の段取りだった（`2026-11-10/comparison-fable-vs-opus.md`）。開始地点、住宅と移住の早さ、特別な市民カードの選択である。
- `score` の見込みには終了時の能力（特別市民05・12・06、資本家など）が入らず、各席が自分で足していた。ゲーム8でも要望に残った。
- 実際に起きた失点に、同じ型の読み違いが繰り返し出ている。自然公園を崩す建設、撃退できるのに防衛を選ぶ、臨時ワーカーで福祉を打って役所の変換が出ない、資源やワーカーを残したままのパスである。
- ゲーム8では、狙っていた特別な市民カード05 を他の席に先に取られ、計画が崩れた席があった。計画は他の席に先を越される前提で立てる必要がある（ユーザーの指摘 2026-11-12）。
- ゲーム8の打ち手1人あたりは約13〜17万トークン・30〜63回の呼び出しだった。選択肢を1つずつ送る打ち手が多く、`move` の回数が増えた。

## 1. 守ること

- ルールを再実装しない。合法手は `getOptions`、進行は `applyMove`、得点は `finalScores`、派生値は `queries` だけから得る。下見と注意は、局面の写しに `applyMove` を掛けた結果を `queries` で比べて作る。`tools/play/` の側で得点や合法性を計算しない。
- 選択肢 ID、選択肢の並び順、番号、乱数の消費順、`Option.label`、記録の形（`ReplayRecord`）を変えない。
- 非公開情報（19-6-1）を、新しい出力のすべてで守る。**下見は、乱数を消費する選択と非公開情報が公開される選択の先を見せない**（2-2）。視点以外の手札の内容と山札の順序を出さない。
- コマンドが出すのは事実（数値とその変化、誰が何を取ったか）だけである。どの手が良いかの助言を出さない。判断は打ち手が行う。
- 既定の出力を長くしない。注意は1回の出力で5行まで、狙いの知らせは3行までとする。`move` の既定の出力（選択肢を除いて15行以内）の検査は、注意と知らせを含めて通ること。
- 新しいライブラリを導入しない。配布用ビルドとオンラインのビルドに含めない。オンライン版の `online show|wait|move` にも、伏せた写しで求められる範囲で同じ出力を適用する（求められないものは出さない）。

## 2. 作るもの

### 2-1. 得点の見込みに終了時の能力を含める（項目2）

- `src/game/` に、いま終局したと仮定したときの最終得点を返す純粋関数を加える（名前の例：`projectedScores(state)`）。局面の写しに終了の手順（17-0-1。最終の収入、ゲーム終了時の能力、自然公園の最大の割り当て、評価軸ごとの換算）を実際に掛けて求め、元の局面を変えない。終了の手順を別に書き直さず、エンジンの既存の処理を通す。
- 終了の手順の途中にプレイヤーの選択が要る効果がある場合は、その効果を含めずに求め、含めなかった効果の名前を返す。該当する効果がいまのデータにあるかを調べ、報告に書く。
- `score`・`resume`・`show --only self` の見込みをこの関数の値に替える。見出しは「いま終わったときの見込み（終了時の能力を含む）」とし、含めなかった効果があればその名前を添える。従来の「終了時の能力を除く」値は出さない。
- 終局した局面では `finalScores` と一致すること。

### 2-2. 手の下見（項目2）

- `move` に `--dry-run` を加える。指定した選択肢を局面の写しに順に適用し、**記録を変えずに**次を出す。
  1. 適用した選択で起きた出来事（既定の `move` と同じ形）
  2. 自分の資源・ワーカー・トラックの増減の合計1行
  3. 自分の得点の見込み（2-1）の増減1行（評価軸ごとの内訳つき）
  4. 適用後に残る選択待ちがあれば、その見出しだけ（選択肢の一覧は出さない）
- 先を見せない規則：次のいずれかに当たる選択の手前で止め、「ここから先は下見できない（理由）」と1行出して、そこまでの結果を出す。
  - 乱数を消費する、または非公開情報が公開される選択（山札から引く、特別な市民カードの補充がめくられる、襲撃カードの公開など）。判定は `isCheckpoint`（`src/game/history.ts`）を土台にし、足りない場合は `src/game/` の側に判定を足す。
  - 選択待ちが他の席に移る選択の後（他の席の手を下見しない）。
- 候補の比べ方：`--or` で区切って最大4通りの手順を渡せる（例：`move --dry-run act:build:normal temp:0 build:house:E3 --or act:welfare:normal temp:0`）。手順ごとに 2・3 を1行ずつ並べ、出来事は省く。途中で選べない選択肢があった手順は、その旨と何個目かを出して他の手順は続ける。
- `--seat` を付けたとき、選択待ちがその席でなければ失敗する（既定の `move` と同じ）。

### 2-3. 落とし穴の注意（項目3）

- 選択肢の欄の後（「選べない〜」の行と同じ位置）に「注意：」の行を出す。対象は、過去の対局で実際に失点になった次の型とする。いずれも局面の写しに選択肢を適用し、`queries` の値を前後で比べて求める。
  1. **自然公園を崩す**：建設・土地タイルの配置・到達報酬の無料建設の選択肢のうち、適用すると自然公園の見込み（`natureParkPoints`）が下がるもの。「E3 に建てると自然公園 8→5点」の形で出す。
  2. **撃退できるのに選ばない**：襲撃の宣言で、撃退の選択肢があるとき。「撃退を選べる（軍事力トークン N 個）」の形で、防衛・宣言なしとの得るものの差を出す。
  3. **役所の変換が出なくなる**：福祉で臨時ワーカーの人数を選ぶ場面で、役所があり、その人数を払うと変換に使える臨時ワーカーが残らないもの。
  4. **残したままのパス**：パスの選択肢があり、使えるワーカーが残っているとき、その人数。最終ラウンドでは、得点にならずに残る金・資材と、まだ使える変換（資材4→臨時ワーカー、手札→資材）を添える。
  5. **強制の建設**：到達報酬などで選ばずに済ませられない建設が次に来るとき（軍事レベル12 の山岳への無料建設など）、その到達の手前の選択肢に「次に山岳へ無料建設が入る」と出す。
- 型の一覧は1か所（`src/game/` の1ファイル。名前の例：`pitfalls.ts`）にまとめ、型ごとに「どの選択待ちで、どの `queries` の値を比べるか」を持つ。カードやキャラクターごとの個別の分岐を書かない。
- 2-2 の「先を見せない規則」に当たる選択肢は、適用して比べない（注意を出さない）。
- 注意は事実だけを書き、「〜すべき」と書かない。1回の出力で5行までとし、越える分は「ほか N 件」とする。`--full` でも同じ位置に出す。
- 計画都市の「形が鏡像になっている」（ゲーム8 P2 の読み違い）は、判定の作りが別になるため本指示書では扱わない（8 の次の候補）。

### 2-4. 狙いの登録と、先を越されたときの知らせ（項目4）

計画は他の席に先に占有されて崩れることがある。打ち手が狙いを登録しておき、先を越されたらコマンドが知らせる。

- `plan --seat <番号> --set <狙い,...>`：狙いを登録する（上書き）。`plan --seat <番号>` は一覧、`plan --seat <番号> --clear` は消す。置き場は `.play/plan-P<席>.json` とし、記録（`ReplayRecord`）には入れない。
- 狙いに書けるもの：アクションスペース（`act:<action>:<tier>`）、公開中の特別な市民カード（`sc:<id>`）、場のボーナスタイル（`bonus:<n>`）、計画都市（`plan:<id>`）。最大8個。知らない書き方は、書ける形を添えて失敗する。
- `wait`・`move`・`resume` の出力の、出来事の後に「狙い：」の行を出す。狙いごとに、いまの状態を1つだけ示す。
  - アクションスペース：空いている／P1 が置いた（占有型でこのラウンドは使えない）／共有で使える／自分が使った
  - 特別な市民カード：公開中／P1 が獲得した／自分が獲得した
  - ボーナスタイル：場にある／P1 が持っている
  - 計画都市：未達成／P1 が1位で達成（残りの順位と点）／自分が達成
- 前回の出力から状態が変わった狙いだけを出す（変わっていなければ行を出さない）。前回どこまで知らせたかは `.play/plan-P<席>.json` に持つ。3行までとする。
- ラウンドが替わったら、アクションスペースの狙いは「空いている」に戻る（消さない）。
- `resume` と、ラウンドの最初の `wait` には、このラウンドの手番順と「自分より先に打つ席」を1行で出す。
- 狙いの状態は公開情報だけから求める（`queries.spaceUsers` など）。足りない派生値は `queries.ts` に足す。

## 3. 運用文書（`docs/playtest/`）

### 3-1. キャラクター別の序盤の定石（項目1）

- `docs/playtest/openings/<キャラクター>.md` を10人分作る。1ファイル1KB 以内とし、次の順に書く。
  1. 第1ラウンドの狙い（達成したい状態を数値で。例：通常ワーカー8人、砦2軒で教練最上位）
  2. 手順（占有型のスペースを先に、共有のスペースを後に）
  3. **先を越されたときの代わりの手**（狙いの占有型スペース・特別な市民カードごとに1つ）
  4. ドラフトで相性の良い個人ボードの特徴とボーナスタイル
  5. 根拠にした対局（ゲーム番号・席・得点）と、観察の数（1局だけ、など）
- 内容は、過去の記録（`replays/`）で各キャラクターの最高得点の席が第1ラウンドに打った手（`log --seat`）と、各席の知見（`insights/`）から作る。記録にない手順を推測で書かない。1局しか観察のないキャラクター（資本家・官僚・精霊使い・豪商・指揮官・デザイナー・芸術家）は、その旨を冒頭に書き、手順ではなく「効いたこと・足りなかったこと」に留めてよい。
- `docs/playtest/openings/draft.md`（1KB 以内）：ドラフトの指針。キャラクターの強弱、個人ボードで見る所（特別な市民カードのマスへの距離など）、ボーナスタイルの選び方。
- 各ファイルの冒頭にデータの版（`DATA_VERSION`）を書く。**main はゲーム8の後に調整案を取り込んでおり、データが変わっている。** 根拠にした対局の版がいまの版と違う場合は、変わった数値に関わる記述を調べ、合わなくなった記述を直すか「調整前の観察」と明記する。
- `knowledge-play.md` は3KB 以内のまま保つ。定石に移した内容（キャラクターごとの記述）は `knowledge-play.md` から削る。

### 3-2. 打ち手への指示（`player-brief.md`）の改訂（項目2〜4）

3KB 以内のまま、次を加える。加えた分は既存の記述を詰めて収める。

- 読むもの：ドラフトの前に `openings/draft.md`、キャラクターが決まったら自分の `openings/<キャラクター>.md` だけを読む。他のキャラクターのファイルは読まない。
- ラウンドの最初に計画を立てる。
  - このラウンドで達成することを2〜3個決め、それぞれに第1候補と、**先を越されたときの代わり**を決める。
  - 占有型のスペース・公開中の特別な市民カード・ボーナスタイルは、他の席に取られうる。取られうるものを先に打ち、共有のスペース（建築・開拓・移住・普及の通常）は後に回す。自分より先に打つ席を見て、初手で押さえるものを決める。
  - 狙いを `plan --set` で登録する。計画はノートの先頭に書く（次のラウンドの打ち手のためではなく、同じラウンドの自分が読み直すため。ラウンドの終わりのノートは従来どおり上書きする）。
- 番が来たら、「狙い：」の行に変化がなければ計画どおりに打ち、考え直さない。変化があれば、崩れた狙いの分だけ代わりに切り替える（計画全体を立て直さない）。
- 迷う手は `move --dry-run ... --or ...` で比べてから打つ。得点の暗算をしない。
- 1手番の選択は、決まっている限り1回の `move` にまとめて送る。
- 「注意：」の行が出たら、その選択肢を選ぶ前に読む。
- 考える量の配分：ドラフト、第1ラウンドの計画、最終ラウンドの使い切りに厚くする。

### 3-3. 対局を回す手順（`docs/playtest/README.md`）

- 作業ディレクトリに `openings/` を写すこと、`.play/plan-P<席>.json` は打ち手が作り直されても残すこと（ラウンドの途中の作り直しに備える）を加える。
- 対局後に `openings/` を見直す手順（新しい観察で手順が変わったら直し、根拠の対局を足す）を加える。

## 4. テスト

`tests/play-cli.test.ts` と、`src/game/` に足した関数の単体テストに加える。

- 見込み：乱択プレイアウトの終局した局面で `projectedScores` が `finalScores` と一致する。途中の局面で呼んでも元の局面（乱数の状態を含む）が変わらない。終了時の能力を持つ特別な市民カード（05・12・06）と資本家について、見込みが能力の分だけ従来の値より大きい。
- 下見：`--dry-run` の後に記録が変わらない。下見の増減が、同じ選択肢を実際に適用した前後の差と一致する。乱数を消費する選択・非公開情報が公開される選択の手前で止まり、その先の出来事（引いたカードの内容など）が出力に現れない。選択待ちが他の席に移った後を適用しない。`--or` の各手順が独立している（1つが失敗しても他が出る）。
- 注意：型ごとに、該当する局面で注意が出て、該当しない局面で出ない。注意に書いた数値が `queries` の値の差と一致する。乱択プレイアウトの全選択待ちで、注意が5行以内、例外を出さない。先を見せない規則に当たる選択肢について注意を出さない。
- 狙い：登録・一覧・消去。他の席がスペースを占有した・特別な市民カードを獲得した・ボーナスタイルを取った・計画都市を達成した後の最初の出力に知らせが出て、次の出力には出ない。ラウンドが替わるとスペースの狙いが戻る。知らせに視点以外の手札の内容が現れない。
- 行数：既定の `move` の出力が、注意と知らせを含めて選択肢を除き15行以内である。
- 非公開情報：`--dry-run`・注意・狙いの知らせ・見込みのすべてで、視点以外の手札のカード番号と名前、山札の順序が現れない。
- 既存の記録：`docs/playtest/` の8局が終局まで再生でき、最終得点が各 README の値と一致する（データの版が違う記録は、既存の扱いに従う）。

## 7. 取り込み後の確認（本指示書の作業の後、別に行う）

- シード 20261120、3人、席・キャラクター・モデルをゲーム8と同じにして、新しい運用で1局打つ。
- トークン量：打ち手1人あたりの量（キャッシュの読み込み・キャッシュの作成・出力・道具の呼び出しの回数）をゲーム8と同じ集計で出す。**ゲーム8を上回らないこと**が条件である。上回った場合は、何が増やしたか（`--dry-run` の回数、定石の読み込み、計画の書き直しなど）を内訳で示す。
- 得点：3席の得点と内訳をゲーム8と並べる。ただし main のデータはゲーム8の後に変わっているため、得点の差は運用の効果とデータの変更の効果を分けられない。その旨を明記し、得点は参考に留める。分けて測る必要があるかは、結果を見てユーザーが決める。
- 使われ方：`--dry-run` と `plan` の使用回数、注意が出た回数とその後に選ばれた手、狙いを先に取られた回数とその後の切り替え、1回の `move` に並べた選択肢の数の平均を出す。
- 打ち手が自作の絞り込みや暗算に頼った箇所、使われなかった機能があれば、足りなかったもの・要らなかったものとして報告する。

## 8. 次の候補（本指示書では作らない）
