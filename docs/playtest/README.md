# 対話プレイの対局の回し方

エージェント同士（または人と AI）で対局し、記録と知見を残す手順である。指示書 2026-11-11（対話プレイ軽量化）と decisions.md 3-5 に基づく。

| ファイル | 内容 |
|---|---|
| `player-brief.md` | 打ち手への指示（3KB 以内）。打ち手の作業ディレクトリに写す |
| `knowledge-play.md` | 打ち手が対局の前に読む知見の要約（3KB 以内）。打ち手の作業ディレクトリに写す |
| `2026-11-10/` | 2026-11-10 の7局の記録・経緯の知見（`knowledge.md`）・各席の知見。打ち手には読ませない |

## 手順

1. ビルドする：リポジトリで `npm run play:build`。`dist-play/cli.js` ができる。
2. 作業ディレクトリを用意する：リポジトリの外に1つ作る（例：`/tmp/play-<日付>/`）。全席がこのディレクトリで起動し、記録 `.play/game.json` を共有する。リポジトリの外で起動するのは、リポジトリの CLAUDE.md（実装向け）を打ち手に読み込ませないためである。ただし、同じセッションから Agent で起動した打ち手には CLAUDE.md が自動で入る（2026-11-11 の確認）。このため CLAUDE.md は約7KB に縮め、領域ごとの約束事を `docs/dev/` に分けた。
3. `player-brief.md` と `knowledge-play.md` を作業ディレクトリに写し、`player-brief.md` の `<席>`・`<作業ディレクトリ>`・`<リポジトリ>` を埋める。
4. 対局を作る：作業ディレクトリで `node <リポジトリ>/dist-play/cli.js new --players 3 --seed <シード>`。
5. 席ごとに打ち手を起動する：作業ディレクトリを起動場所にし、`player-brief.md` を指示として渡す。「いまのラウンド R」を添える（ドラフトと準備は第1ラウンドに含める）。
6. ラウンドごとに作り直す：打ち手は `wait --round R` が「ラウンド R は終わった」と出したらノート（`.play/notes/P<席>.md`）を書いて終える。回す側は R＋1 を渡して新しい打ち手を起動し、新しい打ち手は `resume --seat <席>` とノートから続ける。会話の履歴は持ち越さない。
7. 対局後に回収する：`.play/game.json` を `docs/playtest/<日付>/replays/` に、各席の知見（`.play/insights/P<席>.md`）を `docs/playtest/<日付>/insights/` に置く。`knowledge-play.md` は回す側がまとめて更新する（3KB を越えたら古い内容を削るか統合する）。経緯は `docs/playtest/<日付>/` に別に書く。

## コマンドの要点

- 既定の出力は短い形である。`move` は出来事・自分の要約・次の選択肢だけ、`wait` は他の席の手番を1行ずつと局面を出す。
- 対局中に変わらない文言は `ref`、手札の効果文は `show --only hand`、カードは `ref --card <番号>`。
- 従来の全文は `--full`。打ち手には使わせない（使ったなら、既定の形に足りない情報があったということである）。
- 出力量は `npm run -s play:measure -- --file <記録>` で数える（近似）。

## 確かめていないこと

- ラウンドごとの作り直しとノートの引き継ぎで、打ち手が弱くならないか（指示書 2026-11-11 7。シード 20261120 の1局で、得点と使ったトークン量を 2026-11-10 のゲーム5〜7と比べる）。
