# 効率化の方法のまとめ（ゲーム13、Fable 15人分）

縮小の後の対局で出た案を、重なりの多い順にまとめた。人数は15人中。

| | 案 | 人数 |
|---|---|---|
| C | 指定が「選択肢にない」で止まったとき（`move`・`--dry-run` とも）、その段の選択肢の ID を1行で出す | 9人（P0R1・R2、P1R1・R3・R4・R5、P2R1・R2・R4） |
| D | 指示書の ID の型を補う：建物名（`house` など）・地形名・`temp:N` と `count:N` がいつ要るか・`order:N`・`raid:*`・`space:sc:N#0` | 8人（P0R5、P1R1〜R5、P2R2・R3） |
| A' | `wait`（`--then-wait`）の選択肢を、さらに畳む：狙いのスペースと前回からの差分・`pass`・フリーアクションだけを出し、全一覧は `--only options` | 7人（P0R2・R3・R5、P1R2、P2R3・R4・R5） |
| F | 費用を出す：建物ごとのコスト・建築と開拓の実費（軽減込み）・輸出入の count ごとの受取額・手札の割引後の金額 | 6人（P0R2・R3、P1R5、P2R2・R3・R4） |
| R | `resume`・`ref` に足す・絞る：`ref --only actions:<名前>`・`buildings`（表と残りの軒数）、置けるマスとマスボーナス、ドラフト候補の重複を省く | 5人（P0R4、P1R3・R4、P2R4・R5） |
| D' | `temp:N`・払う量を省いたら既定で補う（通常ワーカーを先に使う） | 3人（P0R3・R4、P2R5） |
| P | `plan --fit PCxx`：計画都市の盤への当てはめ（足りないタイル・建物・マス）を出す | 3人（P0R4、P1R2・R3） |
| G | 定石：資本家（工房3で輸出・最上位が R1 に開く）、デザイナー（土地7枚で建築・最上位）、指揮官（ID の列） | 3人（P0R1、P1R1、P2R1） |

## ゲーム10〜12からの変化

- A（`wait` の縮小）・B（`resume` の短い形）・H（`--then-wait`）は、本局ではほぼ出なかった。採った3案は打ち手の不満としては解消した。
- 代わりに C（止まった段の選択肢の ID）と D（ID の型の補い）が上位になった。ゲーム10〜12 でも6〜7人ずつ出ていた案で、1手番を1回の `move` にまとめるようになったことで、効き目が大きくなった（README の「減らなかった理由」1）。
